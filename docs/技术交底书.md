## 1. 技术名称

一种面向数字逻辑设计的**可追踪 Verilog 组合逻辑数据流图（DFG）构建、结构特征识别与覆盖完整性验证的方法及系统**（并支持“绑定级双域线性度分析”作为可插拔创新扩展）。

## 2. 技术领域

涉及电子设计自动化（EDA）、静态结构分析、逻辑综合辅助、形式化验证与安全分析交叉领域。核心聚焦：对 Verilog 组合逻辑进行自动抽取与 DFG（Data Flow Graph）标准化表示，并在该基础上实现：行号溯源、信号覆盖完整性校验、结构特征（操作符集合、工作集、依赖与潜在融合模式）识别与统一输出。绑定级（Bind-Level）双域线性度分析与掩码编码被定位为“插件式创新扩展”，展示体系可扩展能力，而非核心构建步骤必须项。

## 3. 背景技术

在芯片设计、优化、测试与安全审计过程中，工程师需要：

1. 识别模块内部逻辑的线性/非线性结构，用于算术优化、差分分析、功耗与时延评估。
2. 在 GF(2)（二元域）与算术运算模型之间比较逻辑可线性化程度，支撑密码/混淆检测与可预测性评估。
3. 对比多个版本或多个子模块的结构差异（操作类型分布、叶信号集变动）。
4. 快速定位分析结果与源代码之间的映射（行号、信号名），确保可追踪调试与合规审计。
5. 保证分析覆盖的“完备性”——识别源文件存在但未进入数据流分析的信号并分类说明（常量、别名、未引用等）。

现有工具存在：

- 多依赖综合器或形式验证工具的内部数据结构，黑盒输出、难以定制。
- 线性度分析仅支持单一域，不能双域并行对照。
- 缺少“绑定级（Bind-Level）”粒度的结构掩码（operator mask / workset mask），阻碍批量挖掘与差分编码。
- 缺少统一 JSON 输出集成：行号、可融合邻接、线性度、掩码与覆盖补全信号往往分散。
- 批量模块与历史版本差异分析需手工脚本拼接，效率低。

## 4. 现有技术存在的主要问题

| 问题类别 | 具体表现 | 影响 |
|----------|----------|------|
| 抽取不完整 | 正则/简化解析忽略组合 always、条件/嵌套表达式 | 丢失逻辑，线性度统计偏差 |
| 单域分析 | 仅算术或仅布尔线性 | 无法交叉验证与多视角特征抽取 |
| 不可追踪 | 缺失行号和信号源映射 | 难以溯源与审计、缺陷定位困难 |
| 覆盖盲区 | 未列出“Verilog-only”信号 | 难以评估分析完整性与遗漏风险 |
| 无结构掩码 | 缺乏统一操作/叶子集编码 | 后续聚类、相似度、回归对比困难 |
| 缺少融合提示 | 不输出可融合节点关系 | 阻碍后续逻辑简化/功耗优化 |
| 批处理低效 | 每模块需人工重复命令 | 规模化 SoC 子模块分析吞吐低 |

## 5. 发明目的

核心目的：建立一套高可追踪、结构化、可扩展的 Verilog 组合逻辑 DFG 构建与特征识别流水线，解决“抽取不完整、缺乏行号追踪、覆盖盲区、结构特征缺失、难以二次分析”问题，并形成统一输出协议为后续多种分析（优化、验证、安全、机器学习特征工程）提供基础。

具体目标：

1. 自动抽取 assign 与组合 always，生成稳定 S-expression 形式 DFG；
2. 保留信号及赋值处行号，提供声明/赋值双层优先回退；
3. 结构特征内建提取（操作符集合、叶子工作集、依赖/深度、局部可融合候选）；
4. 覆盖完整性：识别 Verilog-only 信号，分类 alias/constant/declared-only 并输出；
5. 统一 JSON：封装结构 + 溯源 + 覆盖 + 特征；
6. 支持批量模块调度与统计汇总；
7. 通过插件机制无侵入接入增值分析（例如绑定级双域线性度、掩码编码、成本/风险评估）。

扩展目的（创新点演示）：绑定级双域（算术 / GF(2)）线性度分析与掩码表示 → 验证体系插件化与结构特征向量化能力。

## 6. 技术方案概述

### 6.1 总体架构

```text
┌────────────┐  Verilog 源  ┌──────────────┐
│ Verilog AST │────────────▶│ 组合逻辑抽取 │
└─────┬──────┘              └──────┬───────┘
      │ (assign / comb always)     │ Bind (S-Expr)
      ▼                            ▼
┌──────────────┐           ┌────────────────┐
│ DFG 解析构建  │────────▶│ 线性度分析(双域)│
└─────┬────────┘           └──────┬──────────┘
      │ 节点/操作集合              │ 线性标记
      ▼                            ▼
┌──────────────┐           ┌────────────────┐
│ 掩码/融合生成 │           │ 行号/覆盖补全  │
└─────┬────────┘           └──────┬──────────┘
      │ 掩码/邻接                │ 覆盖统计
      ▼                            ▼
           ┌──────────────────────────┐
           │ 统一 JSON 报告 + 可视化 │
           └──────────────────────────┘
```

### 6.2 核心组件（分层：基础构建 vs 插件扩展）

基础构建层：

1. Verilog 抽取器：Pyverilog AST 过滤 assign / 组合 always（排除时序敏感项）。
2. 表达式标准化器：多样运算节点归一为前缀 S-expression（决定性语法）。
3. DFG 构建器：生成节点与引用关系，统计 operator_types 与依赖属性。
4. 行号溯源映射器：构建声明行→赋值行优先回退表。
5. 覆盖补全过程：计算 (Verilog 全集 - DFG 叶子集) 并分类生成合成条目。
6. 结构特征提取器：工作集（workset）、深度、局部模式（潜在融合）。
7. 输出汇编器：组装核心 JSON（结构 / 溯源 / 覆盖 / 特征）。

插件扩展层（可选）：
8. 绑定级双域线性度分析插件；
9. 掩码编码插件（operator_mask / workset_mask）；
10. 可融合邻接分析插件；
11. 其他分析插件（成本估计 / 风险评分 / 聚类特征编码等）。

运行支撑层：
12. 批处理调度与结果汇总；
13. CLI / 可视化接口；
14. 插件注册与隔离（预留接口）。

### 6.4 流程要点（核心 DFG 构建）

1. AST 遍历：过滤 sequential always；组合 always 内递归收集阻塞赋值。
2. 表达式标准化：统一常量格式（如 `32'hFF` → 十进制或保持文本 consistent）。
3. 线性度：递归子树判定，短路策略（任一子非线性即非线性）。
4. 掩码：顺序与首见原则；当前为布尔掩码，可扩编码。
5. 覆盖：集合差 (Verilog 全信号 - Bind 叶子集) 并分类；生成 SYNTHETIC Bind（或单独 coverage 节点）。
6. 融合：基于局部模式表（可扩展多级推理）。
7. 行号：优先赋值出现，否则回退声明；缺失列入 `missing_line_info`。

### 6.5 线性度判定规则（插件示例，非核心构建）

该插件以“只读”方式消费已构建 DFG：

- GF(2) 域允许：XOR / NOT / BUF；禁止：AND / OR / 数据相关 MUX。
- 算术域允许：ADD / SUB / XOR / NEG / BUF；禁止：AND / OR / MUL / 数据相关 MUX。
- Trivial：恒等 / 单叶子 / 常量赋值。

流程：自底向上缓存子树双域线性状态 → 绑定节点产出 (is_linear_arith, is_linear_gf2) 标签 → 可被掩码/统计插件组合使用。

## 7. 关键创新点（基础 vs 插件分层）

基础层：

1. DFG 构建与溯源深度融合：抽取阶段即同时完成行号、引用、覆盖分类，减少多次遍历与丢失风险；
2. 覆盖补全机制结构化：通过“合成条目”显式呈现分析缺口，提升透明度与可审计性；
3. 标准化 S-expression 表达：使得不同模块/版本可直接结构差分与向量化；
4. 内置结构特征（operator_types, workset, depth, fusion patterns）提取内联完成，降低后处理复杂度。

插件层：
5. 绑定级双域线性度分析：单次遍历同时给出算术与 GF(2) 线性标签；
6. 掩码编码（operator_mask / workset_mask）：统一结构/输入特征向量化形式；
7. 可融合邻接分析：局部父子模式识别输出，为后续逻辑合并/功耗优化提供线索；
8. 插件接口统一：扩展分析可无缝挂接并注入 JSON；
9. 结果合并策略：基础字段与插件附加字段保持向后兼容，易于版本进化。

## 10. 具体实施方式

### 实施例 1：ALU 模块（展示核心 + 线性插件）

1. 输入：`alu.v`。  
2. 抽取得到 Bind 数量：81（示例值）。  
3. 算术线性率约 63%，GF(2) 线性率约 56%，trivial ~8.6%。  
4. 覆盖补全：22 个 Verilog-only 信号，全部归类输出。  
5. 生成 JSON 与可视化 PNG。  

### 实施例 2：指令解码模块（仅核心 DFG + 覆盖）

控制信号结构以布尔组合为主，GF(2) 线性比例高于算术线性，说明算术视角下存在与 AND/OR 等非线性节点交互。

### 实施例 3：批处理流程（核心批量 + 可选插件）

使用批处理脚本对多模块（alu, instruction_decode, instruction_pointer 等）逐一执行：

```bash
python tools/verilog_to_dfg.py --input verilog_files/alu.v --out dfg_files/alu_dfg.txt
python esimulator_cli.py analyze dfg_files/alu_dfg.txt --out results/alu_analysis.json
python esimulator_cli.py compare-signals dfg_files/alu_dfg.txt --verilog verilog_files/alu.v --out results/alu_coverage.json
```

脚本自动循环执行上述步骤并汇总 `overall_summary.json`。

### 可选实施例：CASE 展开

CASE 表达式转换为嵌套 (MUX cond_i expr_i prev) 结构，提高分支内差异性线性判定精度。  

### 异常与边界处理

| 情况 | 处理策略 |
|------|----------|
| Pyverilog 未安装 | 提示并退出，不生成 Bind |
| 未识别节点类型 | 标记 GENERIC + 非线性 |
| 行号缺失 | 记录到 missing_line_info |
| 表达式过深 | 可配置深度阈值截断并标注 truncated |

## 11. 算法与复杂度分析

| 阶段 | 时间复杂度 | 说明 |
|------|------------|------|
| AST 抽取 | O(N) | N 为 AST 节点总数 |
| 表达式转换 | O(E) | E 为表达式节点数 |
| 线性判定 | O(E) | 每节点常数次递归 |
| 掩码生成 | O(E_leaf) | 叶子一次去重 |
| 覆盖补全 | O(V) | V 为 Verilog 信号数 |
| 批处理 | Σ(各模块) | 可并行 |

空间复杂度 O(N + V)。

## 12. 可扩展与变型

1. 增强运算集合：支持移位、拼接、部分选择（bit-slice）。  
2. 线性分类细化：线性 vs 仿射（含常量偏移） vs 近线性（单非线性扰动）。  
3. 多层融合检测：递归合并链分析生成“融合区块” ID。  
4. 掩码高阶编码：多比特表示（线性=1，非线性=0，常量=C，别名=A 等）。  
5. 层次化展开：跨模块实例内联实现全芯片逻辑锥。  
6. 安全指标：结合差分均匀性/代数度数输出更深安全特征。  
7. 增量分析：Git 版本差异只重算受影响 Bind。  

## 13. 术语解释

- Bind：单条赋值抽象表达式单元。  
- Workset：Bind 内全部独立叶子信号集合。  
- Trivial Bind：表达式为恒等/常量/单变量透传。  
- Fusable（可融合）：局部结构可在逻辑等价前提下合并以减少节点或级数。  
- Synthetic Signal：源中存在但未在任一 Bind 叶子集中出现的补全信号。  
- GF(2) 线性：在异或与取反（视为加常量）下保持线性闭包。  
- 算术线性：在加减/仿射组合下的线性；乘法与逻辑与/或引入交叉项视为非线性。  

## 14. 工业应用场景

1. 逻辑优化前分析：识别可融合与线性区域，指导综合器参数。  
2. 功耗/延迟模型构建：基于结构掩码特征训练预测模型。  
3. 安全/篡改检测：检测异常非线性热点或结构漂移。  
4. 测试向量生成：区分线性与非线性段，优化测试覆盖率。  
5. 教学与逆向分析：快速揭示历史处理器模块的逻辑结构特征。  

## 15. 实施注意事项

1. 需统一预处理（宏展开、include）以保证行号稳健。  
2. 大型模块建议分块/并行，避免内存峰值。  
3. 可在 CI 中集成，防止结构突变未审计。  
4. 对外输出 JSON 需版本号字段（建议 future: `schema_version`）。  
5. 安全场景可增加哈希签名防止报告篡改。  

## 16. 风险与规避

| 风险 | 影响 | 缓解 |
|------|------|------|
| AST 不支持新语法 | 抽取失败 | 加入 GENERIC 回退并记录日志 |
| 行号偏移 | 溯源失败 | 引入文件哈希与增量校验 |
| 深层表达式栈溢出 | 程序崩溃 | 迭代非递归遍历或深度限制 |
| 覆盖分类误判 | 统计偏差 | 引入二次校验与用户标记覆盖 |

## 18. 结论

本发明首先确立“Verilog 组合逻辑 → 可追踪 DFG（含行号/覆盖/结构特征）”的统一基础抽象，再以插件机制展示可扩展分析（如绑定级双域线性度、掩码编码、融合邻接）。该分层设计兼顾：

1. 基础能力：高保真抽取 + 覆盖透明化 + 结构特征内联；
2. 扩展弹性：分析插件可按需增减，不破坏主 JSON 兼容性；
3. 向量化准备：掩码与特征集合为后续 ML/聚类/回归提供直接输入；
4. 审计追踪：行号与合成覆盖条目消除“黑箱”区域；
5. 工程落地：批处理与统一协议支撑多模块/版本快速迭代对比。

因此，本方案在“DFG 构建 + 结构识别”上形成核心竞争力，同时通过“插件式绑定级创新分析”拓展应用边界，具备显著工程与研究价值。
